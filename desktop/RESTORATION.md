## 補充 RAW 解碼（1.26.1003 build 0924）

- 共用 Go 入口處理 LibRaw 已辨識、但缺少感光資料解碼器的格式，涵蓋本輪 Nikon HE／HE* NEF 與 GoPro GPR。GPR 同步加入匯入清單與兩平台 RAW 辨識，避免誤走一般圖片解析。
- 偵測使用者安裝的 Adobe DNG Converter；缺少時在照片下方提供官方下載入口。完成原廠安裝後可重新偵測，包含列表縮圖重試。一般預覽不自動開對話框。
- 建立保留完整感光資料的無損 DNG 快取，由既有共同 LibRaw 路徑顯影。原始照片、配方識別與匯出 EXIF 保持原來源；快取有內容驗證、容量限制、取消與關閉清理。
- Adobe Converter 未加入產品封裝；免費工具與 DNG SDK 的授權不能視為 Converter 再散布許可。部署方式、其他解碼器選項與本輪實測範圍見 [補充 RAW 解碼紀錄](../engine/verification/raw/supplemental-decoder.md)。

## 資料一致性修正

- 換照片、換目錄、原生開檔及關閉視窗前，提交尚在前端等待的滑桿與裁切；背景結果以照片世代及版本比對，不能覆蓋新選取。
- 關閉視窗的最後一批參數與關閉要求合併為同一筆指令，Go 先套用並保存再關閉，避免非同步事件讓關閉先於滑桿更新。
- 路徑與內容雜湊共同識別照片，同內容副本保持獨立；沿用舊 Go 及 Swift 紀錄時保留裁切、修復、自訂底片與手動調整標記。
- 修正「有已修過標記卻顯示原片」：Swift 的內容識別含 `sha256:` 前綴，Go 原先漏掉前綴而找不到配方。讀取來源標記可恢復先前被空白 Go 紀錄清除的狀態；僅回復無調整且歷史不完整的紀錄，保留 Go 後續編輯及明確重設。開圖後同步保存還原配方與標記，再產生預覽。
- 同一張照片的修復貼片只保存一份。修正先前在 37 款配方重複存放而超過容量的問題；契約單則訊息上限改為 64 MiB。
- 批次套用保留目標照片本身的修復，並同步手動調整標記；復原／重做保存整次交易。
- 修正 MCP 批次調整的 Go 型別轉接，工具要等預覽與 UI 確認完成才回覆。
- 初次前端載入只回報系統語言，不覆蓋已保存或遷移的語言偏好；系統選單沿用既有翻譯資料。
- 原生引擎缺失時，共用 Go 設定與配方仍可使用；不將缺少硬體模組當作整個宿主初始化失敗。

## 預覽顯影與下方進度

- 主預覽先取用列表的同一張縮圖；冷快取共用正在執行的縮圖工作，暖快取直接沿用，不重複解碼。初次顯影完成前，列表可視範圍變動不會清掉這張底圖。
- Swift 依目前配方處理影像；新結果解碼完成後，前端保留底圖，以 0→100% 不透明度逐步顯露套用參數後的照片。狀態更新不會中斷動畫，完成後釋放底圖；不同照片的過期結果不會插入目前畫面。
- 讀圖、更新預覽、主體偵測及顯示結果的等待文字與轉圈，統一放在照片顯示區下方狀態列。主體偵測提供下方取消按鈕，一般預覽不開浮動對話框、不鎖住編輯介面；完成後恢復一般預覽狀態。
- 減少動態效果設定會略過淡入動畫。直方圖、比較原圖、裁切、列表與匯出仍沿用原有操作。

### 縮圖交接的放大跳動修正（2026-10-02）

- 錄影中可見相機內嵌 JPEG 把 3:2 影像放入帶上下黑邊的 4:3 容器；預覽把黑邊計入適應視窗尺寸，交接到沒有補邊的編輯圖時便出現放大感。另修正淡入底圖保留舊像素尺寸、沒有跟著外框重排的問題。
- Go 共用縮圖服務依原檔 TIFF／RAW 尺寸、DNG `DefaultCropSize` 及方向，確認預期移除的區域是黑邊後才正規化。尺寸未知、邊緣有實際內容、全暗或比例變化過大的影像保持原狀；原檔、編輯運算與匯出像素不受影響。兩平台使用同一個入口，快取升為 `thumbnail-v2-content-256`，列表與主預覽沿用同一張修正縮圖。
- 淡入前先對齊當前預覽區；底圖與編輯圖共用置中、縮放及位移規則，外框尺寸變化與使用者縮放都會更新兩層。保留原有不透明度淡入、下方等待提示及裁切完成前維持當前畫面的流程。
- 新增有界尺寸讀取及縮圖黑邊回歸，涵蓋 TIFF 大小端序、SubIFD、旋轉、有理數錯誤、循環目錄、橫直幅黑邊、全暗照片、實際邊緣內容、未知尺寸及重複正規化。
- `engine/verification/thumbnail-padding-smoke.py` 產生帶補邊 JPEG 的橫直幅 Bayer DNG，經真實 Swift 引擎、Go 縮圖服務與 Wails 視窗驗證：原生縮圖為 256×192／192×256，顯示縮圖為 256×171／171×256；初次載入、暖快取及底片切換共 9 個案例通過。本機另以橫直幅 NEF 驗證 9 個切換案例。一般桌面 Smoke 新增淡入中改變寬高、放大及符合視窗的對齊檢查。
- 再以使用者提供的 4 張 DNG 原檔驗證 18 個切換案例，全部由帶補邊的 256×192 縮圖轉為 256×171；人工檢視縮圖亦確認移除的是補邊。46 項桌面 Smoke、相關 Go race／vet、JavaScript／Python 語法、macOS 建置及簽章檢查、Windows x64 交叉編譯通過。本輪沒有執行 Windows 實機測試。彙整：本機 `build/preview-geometry-report.json`。

## 演算效率檢視（2026-10-02）

本輪比對目前 Go 宿主、Swift／Core Image／Metal、C++／Vulkan 及舊 Swift 預覽排程。量測使用本機 M4 Pro、64 GiB 記憶體，兩張使用者提供的 DNG／NEF。這是目前混合版的效能剖析與修正前後比較，沒有把原始碼對照當成舊 Swift App 的直接跑分。

### 已修正的兩個重複工作

1. **Windows 的預覽來源快照破壞解碼快取。** Go 每次建立不同暫存路徑，C++ `sourceKey` 則包含路徑、File ID 及時間，造成同一張照片改參數仍重新解碼。Go 現在於複製來源時同步取得 SHA-256；內容與副檔名相同時沿用 Client 擁有的不可變快照，保持原生 File ID。來源改變、關閉及閒置回收時釋放。快照不放在宿主會刪除的單次輸出目錄；跨磁碟支援複製備援。原檔與匯出交易保持原有保護。
2. **macOS 每次裁切／旋轉都重算未裁切的編輯圖。** 舊 Swift 已有 `previewSourcePayloadCache`，混合引擎漏掉這份重用。現在按來源生命週期、完整非裁切參數、底片、修復內容、遮罩、解析度、政策及計算後端識別，保存最近兩份 JPEG，合計上限 16 MiB。只改裁切／旋轉可重用；變更曝光、修復或加速方式等會失效。主成品仍按目前裁切重新顯影，沒有把裁切挪到顯影後，也沒有增加原尺寸 Float32 快取。

來源快照修正通過實際 Go → 子程序的 File ID 重用測試，包含同大小／同時間但內容改變、輸出目錄刪除、取消、並行替換及關閉清理。Windows 本輪只有 x64 交叉編譯，尚無新實機速度數據。

裁切效能另以修正前後的原生引擎執行相同照片與參數；暖機後依序改成 6°、8°、10°，三個不同裁切工作的中位數如下，沒有把相同參數的 Go 成品快取命中當作加速。兩個後端交換前後版的量測順序，不同平台的時間不混用。

## 2026-10-02 依序執行演算最佳化

本輪沿用上述順序；Go 仍管理桌面與排程，原生計算繼續由 Swift／C++ 處理。

1. **乳劑與顯影**：乳劑的四個子樣本共用重疊鄰格的晶體幾何，保留原本四次取樣、三層模型、種子、累加順序與 FP32。很細的晶體使用原搜尋路徑，避免擴大搜尋範圍。六組 DNG 的 PNG16 比較涵蓋粗細顆粒、旋轉、HDR／曝光與完整解析度，最大通道差異為 0.000336、最大 RMSE 為 0.000000420。顯影反應場曾試驗一次讀回與 GPU 中間快取，但出現最高約 0.0566 的局部通道差異，兩種做法均撤回；目前仍使用原來十二步顯影。
2. **階段快取**：macOS 原生工作階段保留 tone 之前的已完成 FP32 影像與主體遮罩，最多兩份、總上限 128 MiB。亮度、對比、色彩、HDR、暗角與背景模糊可沿用前段；來源、RAW 解碼用途、修復內容、遮罩、尺寸、裁切、底片、強度、曝光、白平衡及運算後端改變會重新計算。未知新參數預設使快取失效。掃描參數仍保守納入前段相依條件，因部分參數也參與底片重建。完整尺寸超出預算時不保存階段影像。
3. **Windows 記憶體與 CPU**：線性來源與相機原片縮放成對保存，最多兩種尺寸、128 MiB；完整尺寸直接借用解碼來源。不再預先配置隨即被覆蓋的成品，也不為相同編輯圖或不需縮放的編碼複製整張影像。共用 C++ CPU 的逐像素、Gaussian、Lanczos 與擴散處理使用同一個最多八執行緒的工作池；小圖及巢狀工作直接執行，每個像素的加總順序不變，錯誤等待所有工作結束後交回呼叫端。Windows GPU 計算路徑仍保留原有語意。
4. **RAW 冷開**：macOS 軟體 RAW 的編輯預覽只解碼原流程已使用的 LibRaw 半尺寸感光資料，完整尺寸由 LibRaw 的尺寸／方向／像素比例處理取得。完整解析度及匯出才解完整資料，且不解碼未使用的半尺寸影像；完整預覽需要主體偵測時仍保留舊遮罩輸入。系統 RAW 解碼方式維持原樣，切換解析度可沿用已解碼來源。Windows 原有完整解碼與色彩流程維持原樣。

十份 RAW（DNG、NEF、CRW、X3F、RAF、RW2、ORF、PEF、ARW、CR3）的新舊預覽，以及 DNG／RAF／NEF 完整解析度輸出，其來源／裁切／輸出尺寸相同，PNG16 像素差異為零。未用相機 JPEG 代替感光解碼，未降低預覽尺寸或編碼品質。

跨平台資料表重新匯出後，既有色彩表、白平衡、色調與框圖數值不變；另補上目前目錄已有、舊色調表漏列的 `gr3-sky-orange`。生成來源指紋同步更新。

## 2026-10-02 乳劑晶體共用的邊界精度修正

四個子樣本改用四分量向量，共用同一格的晶體幾何與曝光取樣。原始逐樣本演算法抽成共用函式，供細晶體及邊界補算使用。保留原本四次取樣、三層模型、種子、晶體搜尋／累加順序與 FP32。

浮點乘加的收縮方式可能使晶體邊緣的距離相差幾個 ULP，進而翻轉「是否命中晶體」的判斷。新路徑用座標尺度與晶體間距計算保守的捨入誤差範圍；若任何子樣本落在這個範圍內，該像素使用原始函式重新計算。這個範圍只用來選擇計算路徑，沒有擴張晶體、變更命中門檻或放寬輸出誤差限制。
